## 1. 为什么要自己做

### 1.1 现成工具的问题（按对自用的影响排序）

| 问题 | 具体表现 | 影响 |
| --- | --- | --- |
| **长篇一致性无人管** | 行业调研结论：10 万字以上"人设不崩 + 伏笔回收 + 节奏稳定"目前**没有稳定解**，最好的工具只能维持 10–30 章不明显跑偏；超过 10 万字逻辑一致性显著下降 | 这是最痛的一条，也是本产品立项的直接原因 |
| **只知道"生成"，不解决"管理"** | 主流工具都是"替作者写"，缺"帮作者管" | 我要的不是枪手，是台账与看门人 |
| **检索成本高** | 找第 3 章某角色的一句承诺要翻几十万字 | 每天都要发生数次，累积损耗巨大 |
| **上下文要手动喂** | 每开一章要么复制粘贴一大段设定，要么让 AI 重新"重新开始" | 打断心流 |
| **平台系工具不中立** | 平台既是"裁判"又是"工具"，AI 能力也普遍保守（怕冲击自身内容生态） | 不敢把创作资产托付给它们 |
| **数据与版权焦虑** | 正文上云、是否用于训练不透明 | 自用工具天然解决：本地优先、自己掌控 |

### 1.2 所以自用版要做什么

> 不追求做成产品，只追求**能陪我写完一本百万字长篇而不崩**。
> 允许粗糙、允许只支持我一个人、允许 UI 朴素；**但设定资产必须结构化沉淀，一致性必须有人守，数据必须留在本地。**

## 2. 定位与设计原则

### 2.1 一句话定位

> **墨枢是一个只为一个人服务的创作工作台：把长篇创作的设定、伏笔、时间线沉淀为结构化资产，用一致性守护保证不写崩，用可挂载的 AI 技能提效。**

### 2.2 设计原则（自用版）

1. **单人优先**：不需要账号、权限、协作、分享、邀请。所有"为多人设计"的东西一律砍掉。
2. **本地优先**：正文与设定默认只存本地；可用纯离线模式；文件级可读可迁移（不锁定在应用里）。
3. **粗糙可接受**：功能可以简陋、交互可以朴素，但要**能用、稳定、不丢稿**。
4. **写作优先**：任何检查与 AI 告警都不许弹窗打断输入，只允许侧栏化 / 下划线化。
5. **一切可回溯**：任何 AI 写入的内容必须可定位、可对比、可一键撤销。
6. **默认保守**：默认不联网、不上传、不自动做不可逆操作。

### 2.3 使用场景（典型的一天）

```
上午：打开作品 → 召回本章设定与前情 → 写 4000 字（偶尔用 /查设定、/续写）
      保存时自动巡检，侧栏提示"第 12 章埋的伏笔已到计划回收卷" → 顺手处理
下午：写不动 → 跑一次"去 AI 味扫描"改稿 → 或让 AI 审稿挑逻辑漏洞
晚上：更新伏笔台账与角色状态 → 生成章节摘要 → 收工
周末：翻一致性报告，核对整体进度；给下卷做规划（规划没齐就不动笔）
```

## 3. 个人验收标准

不做商业指标，只回答一个问题：**这套工具到底有没有让我写得更好、更省事。**

| 维度 | 验收标准 | 怎么验证 |
| --- | --- | --- |
| 不崩 | 在 ≥100 万字作品上跑一致性巡检，真违规检出率 ≥ 70%，误报率 < 15% | 用旧作回放：把已发布的章节当作样本，人工标注已知崩点，看命中情况 |
| 省事 | 查"某角色在第几章说过什么"从"翻稿几分钟"降到 ≤ 1 分钟 | 每次检索实际耗时记录 |
| 提速 | 单章平均耗时下降 ≥ 25% | 写作统计面板同比 |
| 可靠 | 零内容丢失：强杀进程、断电后都能恢复到最后一次保存 | 故意断电/杀进程测试 |
| 顺心 | 巡检告警"有用感"≥ 40%（即至少四成告警我确实会改） | 采纳/豁免的计数比 |

> 北极星（自用版）：**连续写作天数** 与 **周有效创作产出**。前者代表可持续，后者代表真产能。

### 4.2 值得直接借鉴的点

- **作家助手 WriteClaw / NovelBuddy**：技能挂载 + 本地存储 + 对话式下指令的交互形态；2023 年"阅文妙笔"、2025 年"妙笔通鉴"（千万字全书理解）说明"全书理解"是硬需求。
- **FeelFish**：多智能体分工（编辑部/质检部/素材部）、"项目时光机"版本回溯、原生接入多家模型。
- **蛙蛙写作**：作品记忆与作品绑定 + 向量索引召回；Agent/Skill/Tool 三层架构。
- **WorkBuddy 式工作流（个人实践）**：**"规划没交齐，一行正文都不许写"** 的门禁思路、四本台账（剧情追踪/时间线/角色状态/关系网）、5 阶段创作协议（Brief → 查设定 → 起草 → 续写 → 修改）。这套是我最想直接落地的形态。

### 4.3 结论

> 现成工具要么是平台的（不中立、AI 保守），要么是给新手/量产用的（偏"替我写"）。
> 我要的形态是：**编辑器官感够用 + 结构化资产 + 一致性守门 + 自己可控的 AI**。

## 6. 功能需求详述

### M1 作品与章节管理（P0）

1. 作品库：卡片列表（书名、字数、最近编辑、当前卷、连载状态）。
2. 结构：分卷 → 章节两层，支持拖拽排序。
3. 章节元数据：状态（草稿/待检/已发）、本章字数目标、**出场角色**、**关联伏笔**、**POV 视角角色**——这三项是 M4 巡检与 M8 召回的输入，必须可维护。
4. 字数目标：单日目标、单章目标、完本预估。
5. 作品级配置：题材标签、**风格锚点**（统一 AI 生成文风）、门禁强度。

**验收**：300 万字 / 2000 章作品，作品库打开 ≤ 1.5s，章节树滚动不卡。

---

### M2 编辑器（P0）

1. 纯文本 / 轻 Markdown 双模式，内置网文排版规范。
2. 专注模式：隐藏侧栏，打字机滚动（当前行居中）。
3. 自动保存：停止输入 2s 或每 5s 落盘；崩溃后恢复现场（含光标位置）。
4. 分屏对照：左设定/前章，右正文，可拖拽定位。
5. 统计：本章字数、今日字数、连续写作天数、平均时速、有效字数。
6. 校对辅助：错别字/标点/人名三级一致（人设档案 ↔ 正文 ↔ 大纲）。
7. 朗读校对：本地 TTS 朗读当前章。
8. 斜杠指令：`/续写`、`/润色`、`/查设定`、`/查伏笔`、`/巡检`。

**验收**：输入延迟 ≤ 30ms（10 万字章节）；自动保存成功率 ≥ 99.9%；强杀进程后零丢失。

---

### M3 设定集 Story Bible（P0）

**原则：一个设定主题一个文件**（便于按需读取、省上下文、也方便自己直接改文件）。

1. **人物档案（一人一文件）**：基础信息、外貌、性格标签、身世、行为模式、说话风格、能力/等级、**当前状态**（位置/伤势/心理）、**成长线变更记录**、**秘密与已知信息边界**（供 POV 越界检测用）。
2. **关系网**：盟友/敌对/暧昧/背叛，关系随剧情动态变化并记录变更时间点。
3. **世界观规则**：按主题拆文件（地理、势力、历史、力量体系、经济货币链、物品链、禁忌），支持"**硬规则**"标记（违反即高等级告警）。
4. **时间线**：事件按故事内时间排序，与章节双向关联。
5. **术语表**：人名、地名、功法、组织统一登记，作为术语一致性的校验源。
6. **全文语义检索**：跨设定集与正文的关键词 + 向量检索，回答"某角色在第几章做过什么"。
7. **AI 抽取设定**：从既有正文/大纲里抽取候选人物、术语、伏笔，确认后入库。

**验收**：100 万字内关键词检索 ≤ 800ms、语义检索 ≤ 3s；AI 抽取召回率 ≥ 80%。

---

### M4 一致性守护引擎（P0，核心）

**原则**：规则引擎初筛（便宜、确定）→ AI 复核（降误报）→ 分级告警（不打扰心流）。

#### M4.1 六类巡检项

| # | 巡检项 | 说明 | 默认等级 |
| --- | --- | --- | --- |
| C1 | 人设一致性 | 性格、说话风格、能力等级与档案冲突（含"配角隔几十章再出场"的情形） | 高 |
| C2 | 伏笔闭环 | 超期未回收、回收与埋设自相矛盾 | 高 |
| C3 | 术语一致性 | 人名/地名/功法/组织命名不一致（含错别字变体） | 中 |
| C4 | 时间线冲突 | 事件顺序、行程耗时、年龄/季节矛盾 | 高 |
| C5 | 视角信息越界 | POV 角色知道了其信息边界外的信息 | 中 |
| C6 | 设定禁忌违规 | 违反世界观"硬规则"或我自定义的绝对禁忌 | 高 |

#### M4.2 功能点

1. 触发时机：保存时增量巡检；标记"待检"时全量巡检；可配门禁（见 M4.3）。
2. 告警呈现：行内波浪线 + 侧栏问题列表，二级展示**依据**（引用设定条款/前文段落）与修改建议。
3. 处置动作：采纳 / 标记"有意为之"（进白名单，避免重复误报）/ 加入豁免规则。
4. 巡检报告：按章输出评分与问题明细，可导出。
5. 双重校验：规则命中项由低成本模型复核，只有高置信度才升级为高等级告警。
6. **每条告警必须给出可定位依据**——禁止"无凭据报警"。

#### M4.3 门禁是什么（关键说明）

**门禁 = 未通过检查就不允许推进下一步的强制关卡。**

它解决的是"我明明知道会崩，但还是忍不住往下写"这件事。参考个人实践里的做法：**"规划没交齐，一行正文都不许写；正文没过稽核，不许发。"**

可设门禁的位置：

| 门禁 | 触发点 | 挡什么 |
| --- | --- | --- |
| 规划门禁 | 开始写某卷/某章正文前 | 设定、总纲、卷纲、章纲没交齐 → 不让动笔 |
| 章节门禁 | 把章节状态改为"已发"前 | 巡检有高等级问题、去 AI 味没过、字数不达标 → 不让标记完成 |
| 卷门禁 | 一卷结束前 | 本卷伏笔未处理、角色状态/时间线未更新 → 不让进入下一卷 |

三档强度：

- **关闭**：只记录不拦。
- **仅提示**（默认推荐）：弹侧栏提醒 + 需二次确认才能继续。
- **强阻断**：直接不让继续，必须处理或显式豁免。

> **自用场景的推荐配置**：规划门禁用"强阻断"（这一条最值钱），章节门禁用"仅提示"，卷门禁用"强阻断"。因为拦自己的成本为零，收益最大；而章节级强阻断容易在自己状态好的时候碍事。

#### M4.4 验收

- 200 条已知违规样本，检出率 ≥ 70%，误报率 < 15%。
- 单章（4000 字）增量巡检 ≤ 10s，不阻塞输入。

### M5 伏笔台账（P0）

1. 条目字段：名称、埋设章节（可多章）、**计划回收章节/卷**、实际回收状态、关联人物、重要度、备注。
2. 看板：未埋 / 已埋未收 / 已回收 / **超期未收** 分列——一眼看出风险。
3. 超期预警：进入计划回收卷仍无回收动作 → 高亮，并计入 C2 巡检。
4. 正文锚点：正文里可插入伏笔标记，写作时自动携带上下文。
5. 完本核对清单：逐条确认"回收 / 有意留白 / 放弃"。

---

### M6 版本与时光机（P0）

1. 本地版本历史：每次保存生成轻量增量版本，每 N 个版本一个全量快照。
2. 版本对比：逐行 diff；AI 写入的段落必须标注"AI 生成"以便回溯。
3. 回滚：单章 / 整书回滚到任意时间点；回滚前自动创建保护快照。
4. 项目时光机：按时间轴浏览项目演进。
5. 崩溃恢复：异常退出后一键恢复到最后一次良好状态。

**验收**：版本占用 ≤ 正文体积 3 倍；diff 打开 ≤ 2s；回滚可撤销。

---

### M7 AI 能力层（P0）

1. **BYOK 多模型**：自填 Key，支持 DeepSeek / Kimi / Qwen / 豆包 / GPT / Claude / Gemini；也可接本地模型（纯离线）。
2. **分级路由**：架构类任务（大纲、人设、审稿）用强模型；机械类任务（一致性扫描、错别字、去 AI 味）用便宜模型——**省钱又不掉质量**。
3. **自定义 SKILL（文件配置）**：技能用文件定义（提示词模板 + 输入源 + 输出格式 + 可读范围），改文件即可加技能，不需要写代码。允许粗糙，先跑起来。首批技能：
   - 素材类：热梗素材收集、同类作品检索
   - 分析类：榜单鉴赏、情节评论与读者预测聚合
   - 创作类：章节续写、润色改写、配图
   - 质检类：一致性巡检、去 AI 味扫描、AI 审稿
4. **可控性**：所有 AI 修改提供修订前后对照；流式输出 + 随时中止；读写范围限定在作品目录内。
5. 成本可见：月度 token 消耗与费用统计。

---

### M8 长篇记忆（P0）

1. 三层记忆：
   - **作品记忆**：与单部作品绑定（设定集、台账、章节摘要、向量索引）
   - **偏好记忆**：跨作品生效（惯用文风、叙事偏好、禁词）
   - **短期记忆**：会话级，解决窗口限制
2. **按需召回**：不灌全书，而是按本章元数据（出场角色/关联伏笔/当前卷目标）精准召回相关设定。
3. **章节摘要**：每章自动生成 100–200 字摘要，供长线检索与续写衔接。
4. **记忆可见可编辑**：能看到"这次带了哪些设定"，可手动增删。

**验收**：200 万字作品，续写请求上下文组装 ≤ 3s，召回相关性抽检 ≥ 85%。

---

### M9 去 AI 味质检（P1）

不是一键按钮，是多轮扫描：

1. 第一遍：句长节奏（识别机械整齐句）
2. 第二遍：排比/三连密度
3. 第三遍：修饰词与"正确的废话"冗余
4. 附加：模板段落指纹、注水章检测

输出 `规则编号 + 行号 + 原文片段 + 建议`，可定位、可复跑；阈值可调，禁词黑名单可自定义；保留历次扫描结果以量化改进效果。

---

### M10 AI 审稿（P1）

结构化报告：市场潜力、文笔、角色塑造、剧情逻辑、节奏与钩子，每项**引用原文作为证据**；另提供"读者视角挑逻辑漏洞"模式（例：配角能脱困为什么主角不能？这个设定该补还是该改？）。

---

### M11 速记与外设（P2）

全局热键速记浮窗、系统托盘常驻、语音输入（本地 ASR），速记内容可一键归入作品灵感库或设定集。

## 7. 核心流程

### 7.1 章节创作流程（含门禁）

```
新建/打开章 → 按元数据召回设定与前情
   → 写作（可选 AI 续写/润色，全程修订对照）
   → 保存时增量巡检 C1–C6
   → 有问题：侧栏告警 + 依据 → 采纳 / 豁免
   → 标记"待检"：全量巡检 + 去 AI 味 + 审稿
   → 通过 → "已发"；未通过 → 门禁拦截（按强度配置）
   → 更新伏笔台账、角色状态、时间线、章节摘要
```

### 7.2 一致性守护流程（引擎内部）

```
正文变更 → 规则引擎初筛（术语表/时间线/硬规则/伏笔台账 精确比对）
   → 命中项打包 → 低成本模型复核
   → 高置信度 → 分级告警（附依据）
   → 处置 → 反馈回流（白名单/豁免规则/误报样本）
   → 定期复盘检出率与误报率，迭代规则与提示词
```

### 7.3 新书启动流程（规划门禁）

```
建作品 → 生成设定骨架（AI 辅助，人工修订入库）
   → 录入主要人物档案 + 关键伏笔清单 + 世界观硬规则
   → 总纲 → 卷纲 → 章纲
   → 三层规划未齐 → 规划门禁拦住，不许动笔
   → 齐了才进入逐章创作
```

```
应用主界面

│   ├── 伏笔台账
│   ├── AI 技能（SKILL 列表与快捷入口）
│   ├── 质检中心（巡检报告/去AI味/审稿）
│   └── 设置（模型与Key · 存储路径 · 门禁强度 · 隐私）
```

| 阶段 | 内容 | 完成标志 |

## 12. 风险与待决问题

### 12.1 风险

| 风险 | 等级 | 应对 |
| --- | --- | --- |
| 一致性误报高，用两天就不看了 | 高 | 规则初筛 + AI 复核；每条告警给依据；一键豁免与白名单；用旧作误报样本持续迭代 |
| 门禁太严反而写不动 | 中 | 强度可调；规划门禁严、章节门禁松 |
| 模型成本失控 | 中 | 分级路由 + 预算上限 + 便宜模型跑机械任务 |
| 大工程量拖垮自己（做成烂尾工程） | 高 | 严格按阶段推进，每阶段能独立用起来；允许粗糙 |
| 向量检索/嵌入方案选型踩坑 | 中 | 先做关键词检索兜底，再上向量；端侧嵌入优先 |
| 数据丢失或损坏 | 高 | 版本快照 + 自动备份 + 文件级可读；关键目录异机备份 |

### 12.2 待决问题

1. **技术栈**：Electron / Tauri / 原生 Qt ？——影响包体积、内存与系统集成能力。
2. **检索方案**：纯关键词（BM25/倒排）起步，还是直接上端侧嵌入 + 向量库？
3. **门禁默认强度**：确认规划门禁"强阻断"、章节门禁"仅提示"是否顺手。
4. **本地模型**：是否要接本地模型跑纯离线（会显著增加机器负担），还是先用云端 API + BYOK。
5. **巡检的粒度**：每保存都跑（及时但费钱）还是只在"标记待检"时跑（省钱但滞后）。
6. **是否保留"导出"能力**：目前不做平台对接；但至少需要一个"复制整章"或导出 TXT 的手动通道。
